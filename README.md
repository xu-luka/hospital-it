# 医院信息科一体化管理系统

合同台账 + HIS 问题记录 + **机房设备巡检** 一体化管理系统。采用 B/S 架构，内网/单机部署，
单进程、单端口（3131），双击启动即可使用。

原「机房设备巡检系统」已整体并入，共用一套账号、一套数据库、一份备份。

## 功能清单

### 合同台账
- 合同登记：合同编号、名称、分类、甲乙方、金额、签订/开始/到期日期、状态（进行中/已完成/已终止/草稿）等
- 设备明细：每个合同可登记多行设备（名称/型号/数量/单价/备注），自动汇总台数与金额
- 付款记录：按合同记录付款（金额/日期/方式/备注），自动计算已付/未付与付款进度
- 附件管理：每个合同可上传多个附件（≤ 50MB，支持中文文件名），可在线下载
- Excel 导入导出：按模板批量导入合同（含设备多行，同一编号多行自动合并），导出当前筛选结果
- 到期提醒：已过期与 30 天内到期合同自动汇总（工作台横幅 + 到期提醒页面）
- 搜索筛选：按关键词（名称/编号/甲乙方）、分类、状态筛选，支持多种排序与分页

### 问题记录
- 问题工单登记：标题、问题分类（一级：日常软件/日常硬件/政策性接口）、二级模块（可选）、紧急程度、报障科室/人、详细描述
- 分类与模块自定义：下拉末尾「+ 新增分类… / + 新增模块…」可自行录入，保存后全系统立即可用
- 全流程跟踪：待处理 → 处理中 → 已解决 → 已关闭，可退回/重开，自动记录处理人/时间/说明
- 处理记录追加、附件上传与在线预览（图片/PDF/视频/Word/Excel）、工单指派
- 单号按「问题记录时间」生成（支持补录历史问题）
- 批量操作：多选工单批量修改状态

### 工作台
- 双标签总览：合同台账 / 问题记录 两大面板一键切换
- 合同统计：合同总数、进行中、总额、已付/未付、30 天内到期、近 12 个月新增、分类分布
- 问题统计：问题总数、今日新增、待处理/处理中/已解决、近 1 个月每日趋势、分类与紧急程度分布、最近动态

### 系统管理
- 统一账号体系：管理员 / 工程师 / 普通用户三种角色，用户管理与角色权限控制
- 统一操作日志：合同与问题两套业务的关键操作汇总审计
- 修改密码、数据备份（VACUUM 一致快照 + 附件打包 + 轮转保留）

## 技术架构

| 层 | 技术 |
| --- | --- |
| 运行时 | Node.js ≥ 22.5（内置 node:sqlite，零原生编译依赖） |
| Web 框架 | Express 4 |
| 前端 | Vue 3 本地化（免 CDN，无构建步骤） |
| 数据存储 | SQLite 三库（data/contract.db 合同+账号+设备台账、data/his.db 问题库、data/inspect.db 巡检历史）+ uploads/ 附件 |
| 认证 | 手写 JWT（HMAC-SHA256）+ scrypt 密码哈希 |
| 设备采集 | SSH / Redfish(BMC) / vSphere / SNMP-less CLI / MSSQL / Oracle，**跑在独立子进程里**，不阻塞 Web |

部署目标机器无需联网、无需安装数据库服务，node_modules 可整体拷贝。

## 部署步骤

### 1. 拷贝部署包

将整个项目目录拷贝到目标机器任意位置，例如 `D:\hospital-it`。

> 仓库内**不含** `node_modules` 与 `runtime\node.exe`（体积过大且属构建产物）。
> 二选一：
> - 用 `npm install` 拉取依赖，并在目标机器安装 Node.js ≥ 22.5（自带 `node:sqlite`）；
> - 或直接使用项目发布的**免安装部署包**（Release 附件），解压即用，目标机器无需联网、无需装 Node。

### 2. 启动系统

双击 **start.bat**，看到以下输出即启动成功：

```
医院信息科日常管理系统 已启动
本机访问:   http://127.0.0.1:3131
局域网访问: http://<本机IP>:3131
```

首次启动自动初始化数据库与初始管理员账号：

| 账号 | 初始密码 | 角色 | 说明 |
| --- | --- | --- | --- |
| admin | 首次启动时随机生成，打印在启动日志里 | 管理员 | **首登后请立即修改密码** |

> 初始版只保留 `admin` 一个账号；工程师 / 普通用户账号由管理员登录后在「用户管理」中自行新增。
> 需要固定初始口令时，启动前设置环境变量 `ADMIN_PASSWORD` 即可（见 `DEPLOY.md`）。

### 3. 开放防火墙端口（供其他科室电脑访问时）

1. 运行 `wf.msc` → 新建入站规则 → 端口 → TCP → 特定本地端口：`3131` → 允许连接
2. 确认服务器局域网 IP（`ipconfig`），其他电脑访问 `http://<服务器IP>:3131`

## 数据状态（初始版）

本初始版是**干净模板**：业务数据为空、只有一个 `admin` 账号、**不含主密钥**，
整目录拷到任意一台 Windows 电脑都能跑，随装随录。

- 合同台账 / 问题记录 / 技术文档 / 巡检历史：均为空表，首次启动由程序自动建表
- 用户：仅 `admin` 一个账号，其余账号在「用户管理」中自行新增
- 设备台账：为空，部署后在「设备台账」页逐台录入设备与口令
- 数据库文件（`data/*.db`）不随仓库提供，均为运行时生成

## 机房巡检（并入部分）

### 功能入口

侧边栏「机房巡检」组下三项，与合同/工单共用同一套账号：

| 页面 | 说明 | 权限 |
| --- | --- | --- |
| 监控大屏 | 全部设备实时状态、CPU/内存、告警原因；分区折叠筛选、严重项排前并呼吸提醒；可全屏投屏到机房电视 | 全员可见 |
| 设备台账 | 增删改查设备、凭据加密入库、启停巡检、单台连通性自检、巡检参数 | 查看全员，改需管理员 |
| 巡检报告 | 报告列表、在线预览、下载；手工一键生成 | 查看全员，生成需管理员/工程师 |

### 首次部署必须做的两件事

1. **迁移设备清单**（若沿用原巡检系统的 config.json）：
   `npm run migrate:config` —— 把旧版 `config.json` 里的设备与其加密凭据原样搬进数据库台账，会长出一份计数校验报告。
2. **注册每周周报**：
   `npm run register-weekly`（默认每周一 07:30），或按需 `node scripts/register-weekly.js --time 08:00 --day FRI`。

### 安全设计

- 设备口令在库中密文存储（`enc:v1:`），**接口永不下发密文**，页面只能看到「已设置/未设置」
- 主密钥不可用时**拒绝保存任何口令**，宁可让管理员先修好 KeyVault，也不让明文口令落盘
- 台账与报告的每次写操作都进操作日志（含来源 IP），且日志中不出现任何凭据
- 报告下载走路径白名单校验 —— 报告目录与配置同层，穿越成功等同交出整份机房凭据清单

## 备份与恢复

### 备份

- 手动：双击 `backup.bat`（备份到 `backups/`，保留最近 30 份）
- 指定目录：`backup.bat D:\hosp-backup 30`
- 定时备份（推荐）：任务计划程序每 22:00 运行 `node D:\hosp-info-manager\scripts\backup.js D:\hosp-backup 30`

备份内容 = 三库一致快照 + 附件 + 认证密钥 + **secrets/（设备口令主密钥）**，打包为一个 zip。

> ⚠️ `secrets/master.key` 是全部设备口令的唯一解密钥，走 Windows DPAPI LocalMachine，
> **换机器即失效且无法找回**。它是备份里最不能少的一项；建议额外单独离线拷贝一份。
>
> 巡检报告 HTML（data/reports）不进备份 —— 数量多、可随时重新生成；如需留档请单独归档。

### 恢复

1. **先停止服务**（关闭 start.bat 窗口）
2. 解压备份 zip，`contract.db` / `his.db` / `inspect.db` 覆盖 `data\` 下同名字段，
   `uploads\` 覆盖 `uploads\`，`secrets\` 覆盖 `secrets\`
3. 重新启动 start.bat
4. 进入「设备台账」页确认设备仍在、且右侧提示在线票数正常

> 若换机器，设备口令会因 DPAPI 失效而无法解开。必须在**原服务器**上执行
> `secrets\KeyVault.exe export` 导出迁移包，再在新机器 `import`，否则需重新录入凭据。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| start.bat 提示 Node.js not found | 确认 runtime\node.exe 存在（部署包自带）；如已删除则安装 Node.js 22.5+ |
| 提示 node:sqlite 不可用 | Node 版本过低（需 22.5+），请升级或使用自带 runtime |
| 其他电脑打不开 | 检查防火墙 3131 端口入站规则；检查服务器 IP 是否可达 |
| 忘记 admin 密码 | 停止服务，删除 `data\contract.db` 重新启动重建账号（历史合同与问题数据会丢失，慎用）|
| 大屏所有设备都显示「巡检失败」 | 先跑 `npm run check` 看「主密钥可用性」；FAIL 表示 master.key 解不开，需在原服务器 export 后 import |
| 大屏提示「采集子进程未在运行」 | 已自动降级为主进程采集（功能可用但会拖慢页面）；查看服务窗口的子进程报错，或重启服务 |
| 停用某台设备后大屏还有它 | 已修复：写操作会立即重载配置并剔除残留结果。若仍出现请刷新页面 |
| 报告生成一直转圈 | 报告要重新采一遍全部设备，正常耗时数分钟；超过预估预算会自动终止并重启子进程，可在服务窗口看到原因 |

## 技术说明

- 数据全部保存在本地 `data/` 与 `uploads/`，不外传，适合内网环境
- 合同库 users 表为唯一账号体系，问题库账号已并入；JWT 密钥持久化在 `data/.secret`
- 数据库自动启用 WAL 模式，防杀毒软件锁库冲突；中文附件名自动修复
- 合同附件与问题附件分目录存放（uploads/contract、uploads/issue），互不干扰
- **巡检采集跑在独立子进程**（src/inspection/worker.js）：SSH/Redfish/vSphere 一轮要几十秒到几分钟，
  隔离后即使采集崩溃也只是大屏失败，合同/工单/登录完全不受影响；子进程被杀会自动重建
  （10 分钟内连续崩溃超过 5 次则停止自愈并明确告警）。设 `INSPECTION_NO_WORKER=1` 可退回主进程采集
- 设备台账出问题时的应急开关：把 `it_inspect_settings.config_version` 置 0，
  或设环境变量 `INSPECTION_SOURCE=json`，即回到读 `data/inspection.json` 的旧模式
- 巡检间隔默认 60 秒（`INSPECTION_INTERVAL_SEC`），历史快照默认保留 90 天（`INSPECTION_HISTORY_DAYS`）
